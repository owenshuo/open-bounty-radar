# Responsible Contribution Guide

Open Bounty Radar helps contributors decide where their time is most useful. It should not be used to mass-submit low-quality pull requests or bypass a project's contribution rules.

## Before Starting Work

- Read the issue, linked discussions, bounty terms, and repository contribution guide.
- Check whether an existing pull request already solves the issue.
- Reproduce the problem or confirm the requested behavior before writing code.
- Confirm that you have any required account, hardware, dataset, or platform access.
- Prefer issues where your change can be reviewed in a focused pull request.

## While Working

- Keep the pull request small enough for maintainers to review.
- Include tests or a clear verification note.
- Explain how the change addresses the issue and any bounty-specific acceptance criteria.
- Mention related issues and competing pull requests honestly.
- Avoid claiming work that another contributor has already completed.

## When to Skip or Watch

Skip or watch an issue when:

- A competing pull request is already merged, approved, or selected.
- Requirements are unclear and maintainers have not clarified them.
- The issue needs private access you do not have.
- The project asks contributors not to work on the issue yet.
- The likely fix would be too broad for a responsible first pull request.

## Project Ethic

Good bounty participation should leave the upstream project healthier: clearer reproduction steps, better tests, focused code, and respectful maintainer communication. Open Bounty Radar is designed to support that standard.
